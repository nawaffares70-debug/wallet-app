# اختبار إشعارات الحوالة في متصفحين

هذا اختبار واجهة قابل لإعادة التشغيل لمسار الحوالة الحقيقي بين حسابين. يثبت
التحقق الآلي اتصال المتصفح، صلاحية الإشعارات، ظهور Toast، استدعاء WebAudio،
واستدعاء إشعار المتصفح. أمّا سماع النغمة وظهور بطاقة إشعار نظام التشغيل بصريًا
فيحتاجان تشغيل المتصفح بوضع headed وملاحظة بشرية.

## تشغيل سريع

1. شغّل خادم المحفظة على المنفذ 3000:

   ```bash
   PORT=3000 npm start
   ```

2. في طرفية أخرى شغّل:

   ```bash
   npm run verify:transfer-notifications
   ```

   ينشئ الأمر حسابين تجريبيين جديدين، لذلك لا تستخدمه ضد قاعدة إنتاجية. يمكن
   تغيير العنوان عبر `WALLET_TEST_ORIGIN` أو مسار Chromium عبر `CHROMIUM_PATH`.
   تحفظ لقطات النجاح في `artifacts/transfer-notification-evidence/`.

## ما يغطيه الاختبار الآلي

- يفتح سياقَي Chromium مستقلين على نفس الأصل، كبديل لنافذتين/متصفحين.
- ينشئ حسابي مرسل ومستلم، ثم يسجل الدخول بهما من الواجهة.
- يمنح المستلم صلاحية `notifications` ويتحقق من ظهور `الإشعارات مفعّلة`.
- ينفذ تحويلًا حقيقيًا بقيمة `1 YER` باستخدام PIN الحساب التجريبي.
- يتحقق في صفحة المستلم من Toast بعنوان `حوالة جديدة` ونص المبلغ.
- يرصد إنشاء `AudioContext` وبدء oscillator بعد وصول إشعار التحويل.
- يرصد استدعاء `Notification` أو `ServiceWorkerRegistration.showNotification`.
- يلتقط حالة الاتصال ولقطات صفحة المستلم قبل/بعد التحويل وصفحة المرسل بعده.

## نتيجة آخر تشغيل آلي

في 6 سبتمبر 2026 نجح التشغيل على `http://127.0.0.1:3000` بحسابي اختبار
مستقلين:

| التحقق | النتيجة |
| --- | --- |
| تسجيل الدخول في سياقَي Chromium | ✅ نجح |
| إذن إشعارات المستلم | ✅ `granted` |
| تحويل حقيقي بقيمة `1 YER` | ✅ نجح |
| Toast المستلم والرسالة | ✅ ظهر المبلغ والعملة |
| تشغيل WebAudio | ✅ `AudioContext` و oscillator بدأا |
| استدعاء إشعار النظام | ✅ `showNotification` استُدعي |
| حالة Socket.IO | ✅ `إشعارات التحويل متصلة` |
| لقطة بصرية لـ Toast والسند | ✅ حُفظت في مجلد الأدلة |

هذه النتيجة تثبت مسار المتصفح وطلب إشعار النظام، لكنها لا تدّعي أن الصوت
سُمِع فعليًا أو أن بطاقة نظام التشغيل ظهرت؛ كلاهما ضمن قائمة التحقق اليدوي
أدناه لأن التشغيل الآلي يستخدم Chromium headless.

## التحقق اليدوي من الصوت وإشعار النظام

لتغطية الجزأين اللذين لا يمكن إثباتهما بشكل موثوق من Chromium headless:

1. افتح الموقع في نافذتين منفصلتين أو متصفحين عاديين.
2. سجّل الدخول بحسابين مختلفين. استخدم زر `تفعيل الإشعارات 🔔` في نافذة
   المستلم واسمح بالإذن من المتصفح.
3. اترك نافذة المستلم ظاهرة أو صغّرها، ثم نفّذ حوالة حقيقية من نافذة المرسل.
4. سجّل النتيجة في الجدول التالي:

   | العنصر | النتيجة المتوقعة | النتيجة |
   | --- | --- | --- |
   | Toast داخل التطبيق | يظهر `حوالة جديدة` مع المبلغ والعملة | ☐ |
   | الصوت | تُسمع نغمة قصيرة عند وصول الحوالة | ☐ |
   | إشعار النظام | تظهر بطاقة إشعار بعنوان `حوالة جديدة` | ☐ |
   | حالة الاتصال | تبقى `إشعارات التحويل متصلة` | ☐ |

5. أعد الاختبار بحسابين جديدين إذا كانت الحوالة السابقة موجودة في السجل؛ لا
   تعتمد على إشعار تجريبي لإثبات أن حدث التحويل الحقيقي وصل عبر Socket.IO.

## تفسير النتيجة

- نجاح `npm run verify:transfer-notifications` مع فشل الصوت اليدوي يعني أن
  المتصفح أو نظام التشغيل كتم الصوت، وليس أن حدث التحويل لم يصل.
- نجاح Toast والصوت مع غياب إشعار النظام يعني أن إذن الإشعارات أو إعدادات
  إشعارات الموقع/النظام تحتاج مراجعة.
- غياب Toast مع بقاء التحويل ناجحًا يعني أن جلسة Socket.IO في نافذة المستلم
  غير متصلة؛ راجع شارة حالة إشعارات التحويل وسجل المتصفح.
